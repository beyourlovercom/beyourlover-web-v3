# G4.5 — Shoptimizer Dependency Audit Lite

Status: PASS WITH CARRY-FORWARD MIGRATION CONTROLS  
Scope: localdev legacy runtime inspection only; no Production writes.  
Decision: keep Shoptimizer + Shoptimizer Child as legacy/rollback until G14, while driving V3 runtime dependency to zero.

## 1. Runtime identity

- Legacy parent theme: Shoptimizer 2.9.5.
- Legacy active stylesheet: `shoptimizer-child-theme`; template: `shoptimizer`.
- Child theme version header: `092001`.
- V3 target remains standalone `BYL V3 Theme + BYL Platform`, not a Shoptimizer child.
- License/support may be retained during migration; runtime dependency is the thing being retired.

## 2. Legacy child-theme footprint

Observed under the localdev production-derived baseline:

- 140 files total.
- 32 PHP files, roughly 12.4k lines.
- 39 CSS files, roughly 18.6k lines.
- 11 JS files, roughly 764 lines.
- The child is therefore a substantial historical application layer, not a cosmetic override.

Major areas include Header/Footer, front page, page and post templates, product/cart styles, product JS, review enhancements, mini-cart overrides, category sort tooling, cache/debug utilities, tracking injections and custom Woo hooks.

## 3. Data-backed dependencies confirmed in DB

The following are not theoretical theme features; real stored data exists:

- `andy_custom_order`: 53 product categories.
- `andy_display_limit`: 49 product categories.
- `below_category_content`: 20 product categories.
- `_custom_rich_text`: 232 products.
- Child-theme Shoptimizer Customizer state contains about 140 theme mods.

Also observed active legacy settings include sticky header, global search, mobile account icon, single-product AJAX behavior, archive flip image, cross-sells carousel, catalog review counts and top bar. Sticky product add-to-cart is currently disabled.

## 4. Category A — WordPress / WooCommerce native capabilities

These do not justify keeping Shoptimizer and should remain owned by WordPress/WooCommerce or V3 wrappers:

- products, variations, categories, tags, brands, customers, orders and cart data;
- Woo product/variation forms and standard add-to-cart semantics;
- Woo notices, account endpoints, cart/checkout data and payment gateways;
- base reviews/comments and standard related/upsell/cross-sell queries;
- standard pagination, result counts, breadcrumbs and search capability where V3 elects to use them.

## 5. Category B — BYL capabilities that MUST be migrated before theme retirement

These are carry-forward requirements, but should move out of the legacy theme:

1. Category merchandising
   - preserve `andy_custom_order` and `andy_display_limit` data;
   - re-home the category sorter/admin UI into BYL Platform / Andy Core;
   - preserve category-first-page semantics where still desired.

2. Product content semantics
   - ACF `productname` / `subtitle` presentation;
   - 232 `_custom_rich_text` product legal/detail blocks;
   - custom price/savings presentation and the chosen currency-switcher integration;
   - product review presentation/integration after review-system audit.

3. Taxonomy SEO/content
   - preserve and render the 20 populated `below_category_content` values;
   - audit any populated tag/brand equivalent fields before G11;
   - keep URL/canonical/index identity frozen.

4. Commerce interaction
   - cart count refresh semantics after AJAX add-to-cart;
   - final V3 mini-cart/cart-drawer decision;
   - coupon policy: maximum one non-`free` coupon if still business-canonical;
   - checkout Terms/Privacy wording if still canonical;
   - empty-cart UX and discount/savings messaging only if product owner retains them.

5. Shell / navigation
   - header, mobile navigation, account, search, cart and footer are already being rebuilt in G4;
   - no Shoptimizer DOM/hook is allowed as a dependency of the V3 shell.

6. Content / marketing
   - blog subtitle/related-content behavior where retained;
   - GTM / Trustpilot / ad tracking must move to the single analytics bootstrap owner in G9;
   - AffiliateWP compatibility behavior must be audited under G7/G9 rather than live in a theme.

7. Docs / BetterDocs
   - BetterDocs visual Customizer values are present inside the child theme mods and are therefore not portable by theme switch;
   - this is expected: content/URL identity is preserved while BetterDocs runtime/styles are replaced by Andy Core Docs OS in G7.

## 6. Category C — legacy behavior to retire, not migrate

The following must not be copied into V3 merely because it exists today:

- global `http_request_args` forcing `sslverify=false`;
- theme-level SQL timing/debug overlays and query-string admin test endpoints;
- temporary Woo analytics rebuild/import/debug code;
- theme-owned cron experiments;
- theme-level custom `super_cache` implementation;
- duplicate/manual GTM ownership;
- legacy CSS/JS bundles copied wholesale;
- Shoptimizer cart/header/footer DOM and Customizer-generated presentation;
- old theme-specific order-number decoration that appends product SKUs unless separately re-approved against the ERP/order-ID contract;
- obsolete page-builder/template residue and backup files.

## 7. Parent Shoptimizer functions currently being replaced or re-owned

Parent Shoptimizer provides wrappers and hooks for archive sorting/counts, related/upsells, product archive image flips, category content, sticky add-to-cart, search, mobile navigation, account icon, cart drawer/fragments, widgetized footer/top bar, blog/page wrappers and multiple compatibility layers.

V3 policy:

- reuse WooCommerce public APIs and hooks where useful;
- do not port Shoptimizer private DOM/classes/functions;
- reimplement only BYL-required behavior using BYL components and contracts;
- prefer data migration over markup migration.

## 8. Gate ownership

- G4: Header/Footer/Nav/Search/Account/Cart shell replacement.
- G5: reusable product/cart/content UI primitives.
- G6: product/category/blog/page rendering, including ACF and taxonomy-content semantics.
- G7: move business logic out of Child Theme; Docs OS; review/integration retirement work.
- G8: cart/checkout/payment rules and transaction-critical behavior.
- G9: analytics/tracking ownership, performance and accessibility.
- G11: SEO parity for taxonomy/product/content behavior.
- G12/G13: production cutover + hypercare while Shoptimizer remains rollback-capable.
- G14: deactivate/remove Shoptimizer and Child Theme only after zero-dependency verification.

## 9. Final retirement gate

Shoptimizer may be retired only when all are true:

- V3 operates with both Shoptimizer and Shoptimizer Child inactive;
- critical Homepage/Product/Category/Blog/Docs/Cart/Checkout/Account routes pass desktop/mobile UAT;
- the stored dependency counts above are reconciled or intentionally retired with evidence;
- no BYL V3 runtime code calls `shoptimizer_*` functions or requires Shoptimizer markup/classes;
- transaction, SEO, analytics and ERP regression gates pass;
- legacy theme remains rollback-capable through G13, then is retired in G14.

## 10. G4.5 conclusion

**Proceed with the standalone V3 architecture.**

The audit does not justify retaining Shoptimizer as the permanent V3 parent theme. It does prove that the legacy Child Theme contains real BYL business logic and stored data, so retirement must be a controlled extraction rather than a deletion.

Canonical principle:

> Shoptimizer license may be retained; Shoptimizer runtime dependency must reach zero only after every approved BYL capability has an explicit new owner.
