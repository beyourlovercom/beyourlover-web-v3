# Creator Read-only Bridge V1 (Dev ↔ WWW)

Status: source implementation, not authorized production activation. Owner confirmed a new /my-affiliate/ WordPress Page (Dev ID 39938), original WWW /affiliate-area/ unchanged.

## Ownership
WWW AffiliateWP remains the single source of approved affiliate identity, referrals, and payouts. Dev Theme only displays historical data via pinned server-side HTTPS GET requests; no payments, payouts, coupons, or WordPress users are modified.

## Independent keys and activation
The WWW Andy Core provider requires BYL_CREATOR_REMOTE_API_ENABLED=true, BYL_CREATOR_REMOTE_KEY_ID (8–64 restricted characters), and BYL_CREATOR_REMOTE_SIGN_KEY (32+ independently generated bytes) set in protected server configuration.
The Dev Theme consumer requires BYL_CREATOR_REMOTE_ENABLED=true and matching KEY_ID and SIGN_KEY, plus a separate Dev-only BYL_CREATOR_BINDING_KEY (32+ bytes). Defaults OFF. No secrets in GitHub, frontend, client cookies, analytics, or tool logs. Never reuse ERP Connector or AffiliateWP admin keys.

## Identity binding and evidence
Dev and WWW WordPress IDs are different namespaces. A trusted operator must independently verify both sides of one real creator identity. Only then store private Dev user meta _byl_creator_www_binding_v1 as an array of www_user_id, affiliate_id and proof. The proof is HMAC-SHA256 of the canonical string byl-creator-binding-v1|dev_user_id|www_user_id|affiliate_id under the Dev-only BINDING_KEY. There is no public self-binding endpoint. No automatic matching merely by equal email, username, or ID.

The WWW provider checks independently that a real WWW user owns the exact AffiliateWP ID and that account is active. Every returned referral and payout must be owned by that same affiliate; mismatches fail closed. An unauthenticated visitor, WP administrator, unbound shopper, altered proof or API outage sees no private data.

## API contract
GET https://www.beyourlover.com/wp-json/andy-core/v1/creator/history
Canonical ordered query parameters: affiliate_id, wp_user_id, ref_page, pay_page.
Headers: X-BYL-Creator-Key, X-BYL-Creator-Time, X-BYL-Creator-Nonce, X-BYL-Creator-Signature.
Signature: HMAC_SHA256 of GET + newline + exact path-and-query + newline + unix_timestamp + newline + nonce + newline + key_id, signed under the dedicated secret. Allow HTTPS only, no redirects, bounded +/- 120 seconds, replay rejection, 1–1000 page bounds, 12 recent referrals and 4 payouts per page. Do not expose customer or order PII.
