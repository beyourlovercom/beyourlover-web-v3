# P1.3 — Dev payment method presentation V1 (2026-10-08)

## Scope and frozen UI
- One normal **Card** choice in Checkout. For the **first Dev sandbox validation**, WooPayments is the selected Card provider and Stripe is retained as an installed Test Mode fallback, **disabled as a visible checkout Card option**.
- Express wallets (including Apple Pay/Google Pay, WooPay and Amazon Pay where enabled) only on Cart and Checkout; never on PDP.
- PayPal is an independent eligible payment option once the PayPal **Sandbox** client/Webhook connection actually exists. Do not represent it as available merely because the plugin is active or Sandbox is selected.
- **Do not use this Dev configuration as a Production payment-routing decision.** Production provider choice requires gateway reliability evidence and separate Owner approval.

## Verified read-only starting state
- Dev site: `https://dev.beyourlover.com`; Stripe 11.0.1, WooPayments 11.1.0, PayPal Payment Plugins 2.0.27 all active.
- Stripe Card: `enabled=yes; testmode=yes`; Express disabled; saved test credentials retained without reading/logging their contents.
- WooPayments Card: `enabled=yes; test_mode=yes`; express locations included `product,cart,checkout`; `express_checkout_product_methods` included `payment_request,woopay,amazon_pay` — this violates the agreed product-page wallet rule.
- PayPal: `woocommerce_ppcp_api_settings.environment=sandbox`, **Sandbox Client ID / Secret / Webhook ID absent**, hence gateway not registered/available for checkout.
- Dev MU Safety (merged PR #20) remains present and defaults to **zero available gateway / no checkout orders / no external mail** unless a scoped short-lived test permit exists. Permit is currently closed. Woo test order list empty.
