## G2 V1 — Owner-approved activation using normal WordPress screens

**Source:** Extend existing Dev Safety MU plugin at dev/mu-plugins/byl-dev-safety.php. The feature branch alone contains these changes; live Dev remains unchanged until separately approved Dev-only deployment and review. NO www / ERP Production deploy.

### Workflow

1. **Dev administrator**: Through an ordinarily authenticated WordPress admin session, open Tools → BYL Sandbox UAT and press Approve 30-minute test window. The action requires manage_options and a WordPress nonce. It checks the reserved nonprivileged test customer, fewer than six customer-owned test orders, WooPayments enabled and Test Mode. It writes an off-webroot private pending grant without a cookie hash. **Admin approval alone cannot open checkout.**
2. **Separate synthetic test-customer login**: Through regular Dev Woo My Account sign-in as byl-p13@example.invalid, the customer presses Activate Sandbox Test on the dashboard. This is an authenticated nonce-protected POST. The server creates a new random secret, places it in that browser's Secure/HttpOnly/SameSite=Strict/host-only cookie, and stores only a SHA-256 hash in the 0600 private grant. No plaintext cookie or credential is shown in chat, Git, logs or URL.
3. **Scoped Checkout UAT**: Only that original signed-in test user and browser, during the approved short window, can see the single configured WooPayments Test Mode rail. Every other session remains fail-closed, including anonymous browsers, administrators, wrong roles, wrong emails, missing/invalid cookies, or changed Live provider settings. Keep the checkout email byl-p13@example.invalid and maximum six actual customer-owned sandbox orders.
4. **Close**: Dev administrator revokes through the same Tools page immediately after testing, or approval auto-expires after 30 minutes; expired browser cookie cannot open checkout. Verify ordinary browsers still show zero gateways. Site-wide blocked outgoing email/noindex/cache protection stays on.

## P7 outbound WooCommerce Webhook isolation (post first successful Sandbox order)

- **Observed incident:** WooPayments Test Mode order #39923 (`_byl_dev_sandbox_p13=yes`) had four completed `woocommerce_deliver_webhook_async` tasks. Live Dev Woo Webhook objects 3 and 4 are `active`, with `order.created` and `order.updated` topics and delivery target host `webhooks.automizely.com`. ActionScheduler `complete` does not independently prove successful HTTP delivery or a sent customer notification. Never infer zero webhooks from an unavailable Woo helper API.
- **Safety fix:** Within the existing Dev Safety MU, `woocommerce_webhook_should_deliver` at maximal priority blocks normal Woo event processing for orders bearing the exact synthetic marker or exact reserved test billing email (`byl-p13@example.invalid`, case-insensitive), independently. Applies to the exact Dev site in staging, **including WP-Cron/CLI background jobs without an HTTPS request context**, only for `order.*` webhook topics; other Woo orders, production host, and product webhooks retain prior behavior.
- **Limit:** This is WooCommerce's standard pre-delivery filter for events passing through `WC_Webhook::process()`. It does not prove third-party custom direct HTTP calls, provider-side Flow rules, already queued webhook attempts, or customer notification state. Check AfterShip organization WWW-only Store filters and provider-side deliveries separately before P7 final PASS. Leave AfterShip connected/paid flows enabled; no global disable.
- **Regression:** `php tools/dev/tests/p7-sandbox-webhook-isolation-smoke.php` is a no-network mocked WP/Woo test for marker-only, email-only, ordinary order, negative marker, webhook topics, wrong site/non-staging, Cron/CLI without SSL, missing order and existing Woo denials. CI must run it and PHP lint alongside the existing G2 smoke.
- **Safe release gate:** Review/merge source first, then exact-head Dev-only MU replacement with backup, rollback, no DB migration or service restart; private Sandbox permit stays absent. Verify `apply_filters('woocommerce_webhook_should_deliver', true, WC_Webhook(#3), 39923) === false` and same for #4 using a read-only filter invocation, and that a separate ordinary non-synthetic order remains allowed; **never call webhook `process()` or `deliver()`** during test. WWW and ERP Production not in scope.
