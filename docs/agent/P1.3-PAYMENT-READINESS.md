## 3. Approved frozen payment boundaries

- Cart and Checkout are the only wallet display surfaces; **no Apple Pay or Google Pay on PDP**.
- Normal Checkout has one visible Card payment choice; duplicate processor-card entries must not compete. Other eligible methods can be distinct rails.
- Preserve existing ERP Payment Authority / stale-pending / observability / economics contracts. No unreviewed fulfillment or Woo order status mutation.
- Stripe is a reliability-sensitive failover/rail: do not remove it until WooPayments' actual reliability has been demonstrated. The eventual primary/fallback choice is evidence-based, not assumed from fees alone.
- WooCommerce handles gateway activation, server-side authorization/capture, payment method tokenization, order and webhook processing; Andy Commerce can own policy/routing abstraction but **not fake gateway success**.
- All payment SDKs should load only on eligible Cart/Checkout states; check CSP, script conflicts, Apple/Google device eligibility and guest/authenticated checkout.
